# Graphify

Используй Graphify перед широким поиском по исходникам, когда нужно понять
архитектуру, владельца символа, зависимость, затронутые тесты или путь между
модулями. Для узкого вопроса начни с `graphify query "<вопрос>"`; для известного
узла используй `graphify explain "<узел>"`, а для архитектурных хабов —
`graphify god-nodes --top 10`.

## Свежесть и обновление

Перед выводами проверь индекс:

```sh
graphify check-update .
git rev-parse HEAD
```

Сверь текущий commit с маркером в `docs/architecture/CODEBASE_NAVIGATION.md`.
Если `check-update` сообщает о необходимости обновления, маркер не соответствует
рабочему состоянию или после проверки менялся код, выполни:

```sh
graphify update .
```

`update` выполняет AST-извлечение без LLM и API-ключей. Не коммить
`graphify-out/`: это локальный воспроизводимый индекс.

## Зависимости и тесты

Для обратного влияния используй `graphify affected "<узел>" --depth 2`.
Для конкретной цепочки используй `graphify path "<A>" "<B>"`; направление
ребра важно, поэтому при отсутствии пути сначала поменяй узлы местами, а не
считай зависимости отсутствующими. В `explain` и `affected` ищи тестовые файлы
`test/*.test.mjs`, затем открой их и соответствующий модуль: связь в графе
задаёт кандидатов на тесты, но не заменяет проверку сценариев.

## Обязательная сверка

Граф — навигатор, а не источник окончательной истины. Читай исходник напрямую,
когда меняешь код, проверяешь контракт/валидацию, ветвление, направление вызова,
динамический импорт или безопасность. Особенно тщательно сверяй `src/risk/`,
`src/strategy/`, `src/execution/`, `src/config/`, `src/state/` и логирование.
Не используй устаревший индекс для вывода, что файл или зависимость отсутствуют.
