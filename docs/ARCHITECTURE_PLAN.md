# Архитектура: локальный трейд-агент (Telegram → AI → Bybit)

> Статус: план согласован. Фаза 0 готова, Фазы 1–7 впереди.
> Принцип: всё локально, без покупки сервера. Pay-per-use только токены LLM.

## Цель

Пользователь с телефона пишет `/trade-init` в Telegram-бота. Локальный агент
генерирует идеи (DeepSeek Flash), фильтрует их по риску (DeepSeek Pro), шлёт
карточки на апрув, и после `Approve` ставит реальный ордер на Bybit mainnet.
Промпт (правила) самообновляется по итогам закрытых сделок через рефлектор.

## Ключевые решения (согласованы)

1. Порядок: **сначала Node TG-бот, потом n8n** (не наоборот).
2. Рефлектор **предлагает** правки промпта, применяет после N сделок.
3. Модели: **DeepSeek Flash** (идеи) + **DeepSeek Pro** (фильтр риска).
4. Telegram-связь: **polling** (не webhook) — не нужен публичный IP/сервер.

## Ограничения «без сервера» (приняты сознательно)

- Telegram не достучится до localhost → используем polling.
- Комп должен быть включён; выключен = агент спит (ок для MVP).

## Фазы

### Фаза 0 — «Рука» (ГОТОВО ✅)
`scripts/mainnet_smoke.mjs` ставит 0.001 BTC лимит @$60k и отменяет — проверено на mainnet.

### Фаза 1 — Telegram-бот (Node, grammY, polling)
- BotFather → токен бота.
- Node-скрипт `src/telegram/bot.mjs`: polling, команда `/trade-init`, ответ «принял».
- Цель: доказать, что TG → локальный процесс работает.

### Фаза 2 — Flash генерирует идеи
- `/trade-init` → сбор market data (tickers/klines) → вызов DeepSeek Flash.
- Flash возвращает 5–10 идей, каждая = карточка: entry/SL/TP/size/risk/R:R.
- Контракт идеи — строгий JSON (schema, как в `analysis-schema.mjs`).

### Фаза 3 — Pro фильтрует (trading-check)
- Каждая идея → DeepSeek Pro применяет правила (pump-chase, SL-width, range,
  BTC-корреляция, R/R). Выжившие проходят дальше.

### Фаза 4 — Апрув в Telegram
- Выжившие карточки → TG inline-кнопки Approve/Decline.
- TTL 3–5 мин: не апрувнул вовремя = авто-отклонение.

### Фаза 5 — Исполнение через «руку»
- Approve → `placeOrder` (mainnet-логика из smoke) → callback в TG «ордер #id».
- Всегда SL/TP в карточке (широкий структурный SL при 1×, см. риск).

### Фаза 6 — Memory feedback loop (рефлектор)
- После закрытой сделки → дешёвый LLM-вызов анализирует результат.
- Предлагает правку правила → копится в `rules.pending.md`.
- Применяется после N сделок (N=10) или вручную. Не после каждой (защита от шума).

### Фаза 7 — n8n как оркестратор
- Когда логика отлажена в Node — обернуть в n8n (Docker) для визуальности.
- n8n-ноды: TG-trigger → Flash → Pro → апрув-wait → исполнение → callback.

## Риск-правила (якорь неизменен)

- Плечо 1× (ликвидации нет), широкий структурный SL (ниже 24h low + буфер).
- Размер = риск$ / дистанция стопа. Риск ≤ 2% капитала.
- Без стопа = не строим. «Только тейк» ≠ отказ от SL, а широкий SL при 1×.
