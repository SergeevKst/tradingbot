## 3. Результаты исследования репозитория (Phase 1)

Факты, проверенные на `BASE_SHA`:

1. **Что такое Graphify здесь.** Внешний Python-CLI `graphify` 0.9.71 (uv-tool `graphifyy`, `~/.local/bin/graphify`), не зависимость `package.json`. Строит AST-граф кода в `graphify-out/` (`graph.json`, `graph.html`, `GRAPH_REPORT.md`).
2. **Существующий Skill.** Рабочего Skill для Codex нет. Есть плагин `.kilo/plugins/graphify.js` (26 строк) под API Kilo/OpenCode — для Codex неприменим.
3. **Совместимость с Codex.** Бинарь 0.163.0 содержит поддержку `.agents/skills` и `SKILL.md`; репозиторный адаптер по этому пути — корректная точка интеграции.
4. **Существующий индекс.** В клоне отсутствует: `graphify-out/` в `.gitignore:10`, каталога нет.
5. **Актуальность.** Все сохранённые цифры устарели: `docs/ARCHITECTURE_AUDIT.md:30` — 610/1247/31 от `999c4ff`; `.autopilot/ARCHITECTURE.md:28` — 347/939/11 от 2026-09-28. Фактический прогон: 1638/4742/83.
6. **Что индексируется.** 230 файлов: `src/**` (141 `.mjs`, ~22 900 строк), `test/**`, `scripts/**`, `docs/**`, `mcp/**`, конфиги. Секретов, `node_modules`, `data/`, `graphify-out/` в индексе нет.
7. **Установка и вызов.** `graphify update .` (AST-only, без LLM и без сети, ~9–10 с), `query`/`path`/`explain`/`affected`/`god-nodes` для навигации. `graphify install --platform codex` пишет в глобальный конфиг — не использовался.
8. **Зависимости.** Для индексации — только `graphify` + Node ≥20.6. Для тестов — ничего (`node --test`).
9. **Существующие инструменты.** `AGENTS.md` уже содержит правила Graphify (строки 1–12), но описывает индекс как существующий и не даёт маркера свежести. Проблема навигации решалась частично: правила есть, проверяемости нет.
10. **Что действительно нужно.** Маркер свежести, привязанный к `HEAD` (в `graph.json` его нет: ключи только `directed`, `multigraph`, `graph`, `nodes`, `links`, `hyperedges`), адаптер-Skill для Codex, навигационный документ, минимальная правка `AGENTS.md`.

Отдельно зафиксирован эталон тестов: `npm test` на `BASE_SHA` — 554 теста, 550 pass, **3 fail**, 1 skipped (перечень в ТЗ, §2.4). Это критично: базовый набор не зелёный, и любые «3 падения» после работ — не регрессия.

## 4. Качество исходного ТЗ (самооценка)

**Что сработало.** ТЗ (`docs/agent-experiments/flash/CODEX_TASK.md`, 262 строки) содержало проверенное состояние, а не предположения: точные цифры прогона Graphify, отсутствие метаданных о коммите, эталон падающих тестов, перечень разрешённых/запрещённых путей, измеримые критерии приёмки и команды проверки. Codex не потратил ни одного цикла на «разведку неизвестного»: он сразу проверил `graphify update`, обнаружил отсутствие `.agents` и пошёл по шагам.

**Что не сработало.**

1. Не было предусловия «песочница Codex запрещает запись в `.agents/**`» — этого я не знал до первого прогона. Из-за этого два прогона Codex упирались в `EPERM` и отказывались коммитить. Правильнее было заранее проверить запись в целевой каталог пробным прогоном.
2. Критерий 5 («8 разделов + ≥3 примера команд») оказался слишком мягким: формально он выполняется документом на 41 строку без фактических выводов. Понадобился отдельный цикл коррекции.
3. Требование «сделай коммит» не было подкреплено указанием, что делать при частичном блокере, — Codex выбрал буквальное «не коммитить неполное».

**Что подтвердилось полностью.** Отсутствие метаданных о коммите в `graph.json`; необходимость обёртки для свежести; неприменимость `.kilo`-плагина; устаревание сохранённых цифр; эталон 3 падающих тестов (совпал после работ).

## 8. Ограничения Graphify и индекса

1. Граф строится по AST: динамические импорты, вызовы через строки, значения конфигурации и runtime-поведение в нём не отражены.
2. Имена узлов неоднозначны (`TradeProposal` матчится в нескольких контекстах) — навигация требует путей, а не коротких имён.
3. `query` даёт BFS-выдачу с усечением по `--budget`: при широком вопросе возвращаются сотни узлов и полезное теряется в хвосте.
4. Свежесть — самодельная (mtime + `HEAD` в `INDEX_META.json`), штатного маркера Graphify не имеет; ложные «устарело» после checkout/клона возможны.
5. Индекс локальный, в Git не хранится: на новой машине его нужно собрать (`build`), иначе навигация недоступна.
6. Требуется внешний CLI `graphify` 0.9.71; в `package.json` он не закреплён — воспроизводимость зависит от окружения.

5. `graphify` не закреплён как зависимость: на чистой машине без uv-tool индекс не собрать.
6. Нет измерения экономии токенов — сравнение «с индексом / без индекса» не проводилось.
