### Что такое Graphify (проверено)

Graphify — установленный глобально CLI-инструмент построения графа знаний по
кодовой базе. Установка: `graphify 0.9.71`, путь `~/.local/bin/graphify`
(uv-инструмент `graphifyy`).

Проверенные команды (`graphify --help`):

- `graphify update <path>` — повторное AST-извлечение и обновление графа **без
  LLM** (детерминированно, без API-ключей). Флаги: `--force` (перезаписать, даже
  если узлов стало меньше), `--no-cluster` (только сырое извлечение, без
  кластеризации).
- `graphify query "<вопрос>"` — BFS-обход `graphify-out/graph.json`. Флаги:
  `--dfs`, `--budget N` (лимит токенов вывода, по умолчанию 2000), `--graph`.
- `graphify path "A" "B"` — кратчайший путь между двумя узлами.
- `graphify explain "X"` — объяснение узла и его соседей.
- `graphify affected "X"` — обратный обход: кто зависит от `X`. Флаги:
  `--relation R` (повторяемый), `--depth N` (по умолчанию 2), `--graph`.
- `graphify god-nodes` — самые связанные узлы (архитектурные хабы). Флаг `--top N`.
- `graphify tree` — D3-дерево (HTML) по `graph.json`.
- `graphify check-update <path>` — проверка флага необходимости обновления
  (cron-safe, пригодна для проверки свежести).
- `graphify cluster-only <path>` / `graphify label <path>` — повторная
  кластеризация / именование сообществ (требуют LLM-бэкенда; можно `--no-label`).
- `graphify extract <path>` — полное извлечение AST + семантический LLM (для
  CI/скриптов; требует API-ключ бэкенда).
- `graphify export <wiki|html|obsidian|svg|graphml|...>` — экспорт артефактов.
- `graphify install --platform codex` — **пишет только секцию `## graphify` в
  `AGENTS.md`** и больше ничего (скилла `.agents/skills/...` не создаёт).

## 14. Требования к отчётности (финальное сообщение Codex)

В финальном сообщении верни структурированный отчёт:

1. Выполненные шаги и фактические команды.
2. Результат валидации Graphify (версия, работоспособность, что сломалось/починено).
3. Содержимое `graphify-out/` после сборки (какие файлы, размер/число узлов).
4. Минимум 3 примера навигации: запрос → результат → зависимости → сверка с кодом.
5. Подтверждение воспроизводимости индекса (повторная сборка).
6. Созданные/изменённые файлы (полный список).
7. Результаты тестов (команда, число passed/failed, вывод при падении).
8. Маркер свежести (commit) и как проверять актуальность.
9. Ограничения и нерешённые вопросы.
10. Явное подтверждение, что торговая логика и Risk Engine не изменены (или что
    изменено, если была доказанная минимальная правка).
11. Если писал скилл в staging-файл из-за `EPERM` — укажи путь.

Не выдумывай числа токенов, стоимости или результаты тестов: чего не можешь
проверить — помечай «не проверялось».

## 15. Условия отказа и отката

**Остановись и сообщи (не продолжай), если:**

- `git rev-parse HEAD` ≠ BASE_SHA в начале работы;
- `graphify` недоступен в окружении;
- Graphify не работает и не чинится минимальными изменениями (тогда не заменяй его
  сам — сообщи с доказательством сбоя);
- тесты падают из-за твоих изменений — откати свои изменения и сообщи;
- не удаётся установить зависимости;
- любое действие требует выхода за рамки §10 или §9.

**Откат:** любые твои изменения локализованы в §10 (скилл, навигационный документ,
минимальные правки `AGENTS.md`). В случае проблем удали их (`git restore`) и
вернись к чистому состоянию. `graphify-out/` — генерируемый, можно удалить и
пересобрать. Не трогай историю ветки.
